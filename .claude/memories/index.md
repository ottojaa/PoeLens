# Project Memories

Persistent, project-level notes and gotchas worth remembering across sessions. Add an entry here for architectural knowledge or cross-file gotchas; use inline code comments for knowledge specific to a single line or function. (See the Memories Workflow section in `CLAUDE.md`.)

Format each entry as a short dated bullet:

- `YYYY-MM-DD` — <the gotcha / decision / non-obvious fact>.

## Entries

- `2026-11-23` — **Backend tests never go under `app/routes` or `app/plugins`.** Production autoloads every file in both folders and has no dev dependencies, so a test file there crash-loops the server (reverie hit this on 21 Nov 2026). `routes-autoload.test.ts` checks both folders and the autoload ignore pattern. Tests that boot the app use the built `dist` (`src/testing/build-app.ts`), because autoload imports natively and cannot load `.ts`; the backend `test` target therefore depends on `build`.
- `2026-11-23` — **Build `@poelens/shared` before tests.** The backend imports its built `dist/`; a stale build fails with "X is not a function". `nx test` depends on `^build` (nx.json `targetDefaults`), but a hand-run `vitest` does not.
- `2026-11-23` — **Electron ships only the compiled main and preload, and electron-builder bundles a package's `dependencies`.** `apps/web` keeps every renderer dependency in `devDependencies` (Vite bundles them for the hosted app), so the installer carries only Electron main and preload (`build.files` is the `dist-electron` folder). The desktop window loads the hosted app with `loadURL`; the URL comes from `app.isPackaged`, not an env var, so a dev run cannot load production by accident.
- `2026-11-23` — **Yarn is not on PATH:** run `node .yarn/releases/yarn-4.17.1.cjs <args>`. `.yarnrc.yml` has `npmMinimalAgeGate: 14d`: a package version younger than 14 days is refused ("quarantined"), that is the age gate, not npm. `resolutions` pin the `nx`/`@nx/*` ecosystem to 22.4.0 (mismatched minors break the project graph). Workspace scripts only see the bins of their own workspace's dependencies, and `yarn.lock` was seeded from reverie so shared dependencies keep the versions known to work together.
- `2026-11-23` — **`/health` has its own pg pool, not the app's.** `db/health-probe.ts` is a one-connection pool with a 1.5 s connect and query timeout, so `/health` answers "degraded" within about 2 s when Postgres is down or hangs. Putting those limits on the shared pool would cut off bulk writes and chart queries and make API calls fail whenever the pool is busy. Every pg `Pool` needs an `error` listener (an idle-client error otherwise crashes the process).
- `2026-11-23` — **The backend esbuild output is nested:** `@nx/esbuild` with `bundle: false` emits to `apps/backend/dist/apps/backend/src/...` plus a `dist/main.js` shim, so the production migration runner is `node dist/apps/backend/src/db/migrate.js`. `config/env.ts` walks upward to find the repo-root `.env`, because `__dirname` differs between tsx runs and the build.
- `2026-11-23` — **Do not add a `vitest.config.ts` next to `apps/web/vite.config.mts`:** the `@nx/vite` plugin would use it as the config for the inferred build and fail with "Could not resolve entry module index.html". The `test` block lives in `vite.config.mts`. The shared and backend projects have their own `vitest.config.ts`.
- `2026-11-23` — **A production web build fails without `VITE_API_URL`** (`apps/web/vite.config.mts`; empty means same-origin). A bundle with the wrong API host only shows up as an API that looks down, so the build refuses instead of defaulting. Dev and tests default to `http://localhost:3100`. Pass it as a Docker build argument when the web image is added.
- `2026-11-23` — **Unchanged poe.ninja bodies are not stored, so a row's `asOf` is the fetch time of the last body that changed,** not of the last poll. A body whose hash matches the latest archived one (or a 304) adds no raw row and no price rows; only the ETag moves.
- `2026-11-23` — **Autoload's `autohooks.ts` needs `fastify-plugin`.** Autoload only marks a plain-function hook as un-encapsulated when it `require`s it; Vitest makes it `import()` the file as an ES module, so without `fp` the hook silently applies to nothing and the production refusal of `/prices/*` never fires. Autoload also prefixes routes with their folder name (`routes/prices/table.route.ts` is `/prices/table`), so route paths inside the folder must not repeat `/prices`.
- `2026-11-23` — **Stale `running` collector rows are abandoned only after the advisory lock is held,** since holding it proves no cycle is live. The lock sits on a dedicated one-connection pool for the whole cycle so it never competes with API queries.
- `2026-11-23` — **Search lowers `pg_trgm.word_similarity_threshold` to 0.4 per transaction** (`set_config(..., true)`): the default 0.6 rejects "divne" (it scores 0.5 against "Divine Orb"). Stash items have the unique's name in `name` ("Winter's Bite") and the base in `baseType` ("Glass Shank"), so search matches both.
- `2026-11-23` — **Low confidence:** stash lines with fewer than 5 listings, and exchange lines trading under 1 unit. Flagged at write time; reads drop them unless asked. poe.ninja exchange images are on `web.poecdn.com`.
- `2026-11-24` — **Latest-snapshot reads must carry the snapshot `time` as well as `raw_id`.** `prices.time` equals the raw row's `fetched_at`; without `p.time = ANY(...)` TimescaleDB cannot exclude chunks and decompresses old ones. The snapshot lookup relies on the partial index `raw_responses_snapshot_idx` (migration 006).
- `2026-11-24` — **A replayed (reparsed) leagues body must not move `current` backwards.** `upsertLeagues` only changes `current` and `last_seen` when the body is not older than the newest stored `last_seen`; the newest body answers 304 later and would never be applied again.
- `2026-11-24` — **Refresh tokens are opaque rows, not JWTs, and `@fastify/jwt` is registered without its `cookie` option.** Only the 15-minute access token is a JWT, read from `Authorization: Bearer` alone, so the refresh cookie can never authenticate a request (a refresh token sent as Bearer is a 401, tested). Refresh tokens are 32 random bytes stored as sha256 and rotated with a one-use `DELETE ... RETURNING`.
- `2026-11-24` — **Session lock order is user row first.** Rotation locks the user `FOR SHARE` before deleting the token; deactivation and reset `UPDATE users` before deleting tokens; `startSession` re-checks `is_active` and the verified `password_hash` under that lock. Taking them in the other order deadlocks (Postgres aborts one side with a 500). A login that was verifying bcrypt while a reset committed must not mint a token for the old password.
- `2026-11-24` — **`trustProxy: 1` lives in `app/server-options.ts` and is spread into both `main.ts` and `testing/build-app.ts`,** so the test app and production agree on what `request.ip` is (the rightmost `X-Forwarded-For` entry, the one nginx appends). Rate limits key on it. Setting it in one place only makes the spoof test pass against a server that production does not run.
- `2026-11-24` — **The error handler must pass Fastify and plugin 4xx errors through** (`app/plugins/error-handler.ts`): `@fastify/rate-limit` throws a plain error with `statusCode: 429`, which an unknown-error branch turned into a 500. The rate-limit plugin is not registered in development, which also switches off the per-route limits (login, register, reset, invite peek), so a dev run never answers 429.
- `2026-11-24` — **The first admin comes from `services/auth/bootstrap-admin.js`** (an extra esbuild entry in `project.json`): `node apps/backend/dist/apps/backend/src/services/auth/bootstrap-admin.js`, run inside the container like `migrate.js`. It prints an invite path, replaces an earlier unused bootstrap invite, and refuses while an active admin exists (with every admin deactivated it is the way back in).
- `2026-11-24` — **The web access token lives in memory only; refresh is single-flight** (`lib/api/session.ts`): one in-flight promise per tab plus `navigator.locks` across tabs, because refresh tokens are single-use and React StrictMode mounts effects twice. Sign-in and link pages call with `skipRefresh`, so a wrong password is not mistaken for an expired session. The dev API and web must share a host (`127.0.0.1` for both, or `localhost` for both): the lax refresh cookie is not sent between different sites.
- `2026-11-24` — **Tailwind's palette is removed (`--color-*: initial`), so a token with no `--color-x: var(--x)` mapping in `styles.css` silently produces no utilities.** `theme.test.ts` asserts every `COLOR_TOKENS` entry is mapped; the same test fails on any hex, `rgb()`/`oklch()`, font family or palette utility (`text-white`, `bg-zinc-900`) under `src/` outside `src/theme/`. Dark-mode contrast is gated against the surfaces (background, card), not the hover level (`--accent`): `--up` on `#2e2e2e` is only 4.45:1.
- `2026-11-24` — **`apps/web` Vitest only collects `.test.ts`, never `.test.tsx`, and runs in node.** A component test written as `.test.tsx` passes by not running. Use `createElement` + `renderToString`, or pure functions. Motion needs `requestAnimationFrame`, which node lacks: stub it in `vi.hoisted` before the motion import, or `animate()` never ticks.
- `2026-11-24` — **Imperative `animate()` ignores `MotionConfig reducedMotion`,** and tw-animate-css overlays ignore Motion entirely. `AnimatedNumber` checks `useReducedMotion()` itself, and `motion.css` pins the `--tw-enter-*` / `--tw-exit-*` custom properties to neutral inside `prefers-reduced-motion` so Radix overlays keep only their fade (sheets and dialogs therefore need an explicit `fade-in-0`, or they would just appear).
- `2026-11-24` — **Vite's dev server refused the fonts (403 "outside of Vite serving allow list")** because they live in the repo-root `node_modules`, outside `apps/web`; `server.fs.allow` in `vite.config.mts` now includes the repo root. Without it the app silently falls back to the system font in dev.
- `2026-11-24` — **The category list is in `@poelens/shared` (`CATEGORIES`) and the collector's requests are derived from it.** `poe2.test.ts` pins the old hard-coded type lists, so reordering or renaming an `id` changes what is fetched and fails that test. `PrecursorTablets` is fetched from the stash endpoint but sits in the Economy sidebar group (`endpoint` and `group` are independent).
- `2026-11-24` — **Sparklines and history share `loadBucketedPrices` (`services/prices/series.ts`),** with history's exclusive `to`. The sparkline window is whole UTC days `[startOfUtcDay(snapshot) - 6d, +1d)`, so `/prices/history?bucket=day&from=<from>&to=<to>` returns exactly the sparkline's points. A `time <= snapshot` bound would need a second mode in the shared query.
- `2026-11-24` — **`routeTree.gen.ts` is tracked and regenerated by the Vite router plugin during `nx build @poelens/web` (set `VITE_API_URL=`),** not by `tsc` or lint. Adding a route file without building leaves typed `Link`s failing to compile.
- `2026-11-24` — **Motion's `useReducedMotion` reads the media query once and never updates,** so a mid-count change never re-renders. `AnimatedNumber` keeps the flag in a ref read when a count starts, and its effect depends on `[value, motionValue]` only; the test mocks `useReducedMotion` because flipping `matchMedia` cannot fail on this Motion version.
- `2026-11-24` — **Chart selectors in shadcn's chart template (`[&_.recharts-...]` with hex colours) trip `theme.test.ts`;** `components/ui/chart.tsx` drops them and colours come from `--color-<key>` plus `--chart-*` tokens.
- `2026-11-24` — **A dev database made before the account migrations has no `users` table:** run `nx run @poelens/backend:migrate` before logging in, or sign-in answers 500.
- `2026-11-24` — **Unknown league is a 404 on `/prices/table`; a known league without snapshots is a 200 with no rows.** The web page shows "This league does not exist" for the first and "No prices here yet" for the second. In the palette test, clicking the header before Ctrl+K opens the palette by click, and the shortcut then closes it.
- `2026-11-24` — **With `keepPreviousData`, the rows on screen belong to the previous scope until the new answer lands, so labels and `AnimatedNumber` keys must come from the response (`data.unit`, `data.league.name`, `data.category`, `row.item.id`), never from the URL.** Keying on the URL labels old numbers with the new unit and then counts every cell. A different category or item is treated as loading, not shown.
