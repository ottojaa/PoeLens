# Web App (React, plus the Electron shell)

The web app is the only UI build. The desktop app is a window that loads it: `http://localhost:4300` in dev, `https://poelens.com` when packaged (`app.isPackaged`). There is no `file://` copy, no hash history and no Vite `base` switch.

## Core Libraries

- **Routing**: TanStack Router, file-based routes in `src/routes/`; `routeTree.gen.ts` is generated by the Vite plugin and committed (prettier and eslint ignore it)
- **Data Fetching**: TanStack Query for all API calls
- **UI Components**: shadcn/ui (`components/ui/`, new-york style: button, badge, card, input, label, skeleton, dialog, sheet, command (cmdk), dropdown-menu), Tailwind CSS v4
- **Theme**: themes are data in `src/theme/` (see Theming below)
- **Motion**: the `motion` package, only through `src/motion/` (see Motion below)
- **Fonts**: Geist, self-hosted via `@fontsource/geist` (weights imported in `main.tsx`); never import fonts from a CDN (a self-hosted app must not call third parties on every load, and the desktop app has to work offline)

## File Structure

```
src/
  routes/        # file routes (__root.tsx is the layout)
  components/
    ui/          # shadcn components
    layout/      # AppShell (signed in), PublicLayout (/login, /invite, /reset), Header, Sidebar, CommandPalette, ...
    brand/       # the wordmark and logo mark
  theme/         # themes.ts (registry), <id>.css (one per theme), audit.ts, theme.test.ts
  motion/        # tokens.ts, motion.css, MotionProvider, PageTransition, AnimatedNumber, AnimatedList, TogglePop
  lib/           # api client and hooks, theme provider, utilities
electron/        # main.mts, preload.cts, navigation.mts (+ test); compiled by electron/tsconfig.json
```

## Data Fetching

Always go through `fetchApi(path, Schema)` (`lib/api/client.ts`): it validates the response against the Zod schema from `@poelens/shared` and throws on a non-2xx status, so contract drift fails loudly. The base URL is `VITE_API_URL`, else `http://localhost:3100`. A production build refuses to run without `VITE_API_URL` (`vite.config.mts`); set it empty for same-origin.

```typescript
export function useHealth() {
    return useQuery({
        queryKey: ['health'],
        queryFn: () => fetchApi('/health', HealthResponseSchema),
        refetchInterval: 30_000,
    });
}
```

Every data view handles loading (Skeleton), error (message and retry) and the loaded state.

## Component Patterns

- Use shadcn components from `components/ui/`; install missing ones first: `npx shadcn@latest add <component>`
- **Never use native `<button>`, `<input>` or `<textarea>`**: use `Button`, `Input`, `Textarea`. Icon-only buttons need an `aria-label`.
- Functional components only; extract reusable logic into hooks
- The footer carries the GGG notice and the poe.ninja credit on every page

## Theming

Colours and fonts are theme data, and nothing outside `src/theme/` may write one.

- **A theme is `src/theme/<id>.css`** plus an entry in `THEMES` (`themes.ts`, `{ id, label }`, for a later picker) and an `@import` in `styles.css`. `[data-theme='<id>']` holds the **light** values and `[data-theme='<id>'].dark` holds the **dark** values; dark is the default. The `.dark` class (toggled by `lib/theme.tsx`, set before first paint by the script in `index.html`, which also sets `data-theme`) and the `@custom-variant dark` stay.
- **Tokens** are shadcn's own names (`background`, `card`, `popover`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`, ...) plus `success`, `warning`, `up`, `down` (price rises and falls: blue and orange, always with an arrow, never colour alone), `scrim` (overlay backdrop), `chart-1..5`, and the fonts `--font-title` and `--font-body`. `COLOR_TOKENS` in `themes.ts` is the list. Reverie's three charcoal levels map to `background` / `card` + `popover` / `secondary` + `muted`, `accent` is the hover level, and **`primary` is the teal accent** (not shadcn's `accent`).
- **`styles.css`** removes Tailwind's built-in palette (`@theme { --color-*: initial }`), so `bg-red-500` or `text-white` produce nothing, and maps every token (`--color-x: var(--x)` inside `@theme inline`). A new token needs its mapping, or its utilities silently do not exist.
- **Use utilities by meaning**: `text-destructive-foreground` on `bg-destructive`, `bg-scrim` for overlay backdrops, `font-heading` (not a font-family) for titles.
- **`src/theme/theme.test.ts` is the gate.** It checks every token exists in both variants, contrast (4.5:1 for text and controls, 3:1 for the focus ring and chart series, each against the surfaces they sit on), that `styles.css` maps every token, and that no file under `src/` (outside `src/theme/`) has a hex or `rgb()`/`oklch()` colour, a font family, or a Tailwind palette utility (`text-white`, `bg-zinc-900`, `bg-[#123]`). When contrast and a design's exact light value disagree, contrast wins and the difference is listed in the PR.
- The Electron window background (`electron/main.mts`) is the one hex literal outside `src/`, and the test keeps it equal to the default theme's dark `--background`.

## Layout

`routes/__root.tsx` picks the frame: signed-in pages get `AppShell` (header with wordmark, league switcher, command palette trigger, unit toggle, account menu and theme toggle; a sidebar of categories from `@poelens/shared`, a Sheet drawer below `md`; the footer), and `/login`, `/invite/$token`, `/reset/$token` (and everything while signed out or loading) get `PublicLayout`: wordmark, theme toggle, footer. `isPublicPath` in `AuthGate` is the one list of public pages.

League switcher, unit toggle and category navigation are **controlled, presentational** components (`value` / `onChange`). They render `disabled` with a visible "soon" label until the economy view owns their state; a disabled button gets no hover events, so a tooltip would never show. The command palette (Dialog + cmdk) opens on Cmd+K and Ctrl+K.

## Motion

All animation goes through `src/motion/`; the numbers live in `tokens.ts` (seconds, for Motion) and `motion.css` (CSS variables, for Radix overlays), and `motion.test.ts` keeps the two equal.

- **Page transitions** (`PageTransition`): a `motion.div` keyed on the matched route fades in and rises 8px over 180ms. Enter only; no `AnimatePresence` exit (it would hold the old page on screen).
- **`AnimatedNumber`**: counts over 400ms through a MotionValue (an interrupted count continues from the number on screen), writing the text node directly (no re-render per frame), and underlines itself once in the accent colour when the value changes; a re-render with the same value does nothing. Screen readers get the final value only.
- **`AnimatedList`**: layout animation for **short lists only** (`MAX_ANIMATED_ITEMS`, 50); layout measures every item on every render, so the economy table must never use it.
- **`TogglePop`**: the spring a toggle's icon pops with.
- **Overlays** (Dialog, Sheet, DropdownMenu) animate in CSS through `tw-animate-css` with `duration-(--motion-...)` and `ease-(--ease-out)`. The palette fades in from 98% over 140ms.
- **Reduced motion** leaves fades only: `MotionProvider` sets `MotionConfig reducedMotion="user"` (Motion drops transforms and keeps opacity), `AnimatedNumber` checks `useReducedMotion()` itself because imperative `animate()` ignores `MotionConfig`, and one `@media (prefers-reduced-motion: reduce)` rule in `motion.css` pins tw-animate's `--tw-enter-*` / `--tw-exit-*` translate, scale and rotate to neutral.
- Only the chart draw-in timing (`--motion-chart`, 600ms) exists so far; there is no chart primitive.

## Electron

- `electron/main.mts` (ESM) loads the hosted app with `loadURL`; the preload is `.cts` (sandboxed preloads must be CommonJS) and exposes only `platform`
- `decideNavigation(url, appUrl)` in `navigation.mts` is the one place that decides `allow | external | block`; `will-navigate`, `will-redirect` and `setWindowOpenHandler` all use it. It compares parsed origins, never string prefixes. Keep `contextIsolation` on and `nodeIntegration` off.
- electron-builder ships only `dist-electron/**/*`, and bundles a package's `dependencies`: keep all renderer dependencies in `devDependencies`
- `nx run @poelens/web:serve:electron` for dev; `build:electron` is `tsc -p electron/tsconfig.json`
- Never launch Electron or a browser from automated runs that forbid it; test the decision logic instead

## Tests

Vitest, configured in `vite.config.mts` (do not add a separate `vitest.config.ts`: the `@nx/vite` plugin would take it as the config for the build). Tests: `src/**/*.test.ts` and `electron/**/*.test.ts`. **A `.test.tsx` file is silently never collected**, and the environment is node (no DOM), so test components with `renderToString` from `react-dom/server` via `createElement` in a `.test.ts`, or test pure functions. Motion's frame loop needs `requestAnimationFrame`: stub it in `vi.hoisted` before the imports (see `motion.test.ts`).
