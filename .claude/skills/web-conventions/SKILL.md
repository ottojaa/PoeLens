# Web App (React, plus the Electron shell)

The web app is the only UI build. The desktop app is a window that loads it: `http://localhost:4300` in dev, `https://poelens.com` when packaged (`app.isPackaged`). There is no `file://` copy, no hash history and no Vite `base` switch.

## Core Libraries

- **Routing**: TanStack Router, file-based routes in `src/routes/`; `routeTree.gen.ts` is generated by the Vite plugin and committed (prettier and eslint ignore it)
- **Data Fetching**: TanStack Query for all API calls
- **UI Components**: shadcn/ui (`components/ui/`, new-york style), Tailwind CSS v4 with oklch variables in `styles.css`
- **Fonts**: self-hosted via `@fontsource/inter`; never import fonts from a CDN (a self-hosted app must not call third parties on every load, and the desktop app has to work offline)

## File Structure

```
src/
  routes/        # file routes (__root.tsx is the layout)
  components/
    ui/          # shadcn components
    layout/      # Header, Footer, ThemeToggle
  lib/           # api client and hooks, theme, utilities
electron/        # main.mts, preload.cts, navigation.mts (+ test); compiled by electron/tsconfig.json
```

## Data Fetching

Always go through `fetchApi(path, Schema)` (`lib/api/client.ts`): it validates the response against the Zod schema from `@poelens/shared` and throws on a non-2xx status, so contract drift fails loudly. The base URL is `VITE_API_URL`, else `http://localhost:3100`. A production build refuses to run without `VITE_API_URL` (`vite.config.mts`); set it empty for same-origin.

```typescript
export function useHealth() {
    return useQuery({
        queryKey: ['health'],
        queryFn: () => fetchApi('/health', HealthResponseSchema),
        refetchInterval: 30_000,
    });
}
```

Every data view handles loading (Skeleton), error (message and retry) and the loaded state.

## Component Patterns

- Use shadcn components from `components/ui/`; install missing ones first: `npx shadcn@latest add <component>`
- **Never use native `<button>`, `<input>` or `<textarea>`**: use `Button`, `Input`, `Textarea`. Icon-only buttons need an `aria-label`.
- Functional components only; extract reusable logic into hooks
- Theme: dark by default (warm near-black, gold accent), light mode via the header toggle (`lib/theme.tsx`, stored in `poelens-theme`); use the semantic tokens (`bg-background`, `text-muted-foreground`, `success`, `warning`), not raw colours
- The footer carries the GGG notice and the poe.ninja credit on every page

## Electron

- `electron/main.mts` (ESM) loads the hosted app with `loadURL`; the preload is `.cts` (sandboxed preloads must be CommonJS) and exposes only `platform`
- `decideNavigation(url, appUrl)` in `navigation.mts` is the one place that decides `allow | external | block`; `will-navigate`, `will-redirect` and `setWindowOpenHandler` all use it. It compares parsed origins, never string prefixes. Keep `contextIsolation` on and `nodeIntegration` off.
- electron-builder ships only `dist-electron/**/*`, and bundles a package's `dependencies`: keep all renderer dependencies in `devDependencies`
- `nx run @poelens/web:serve:electron` for dev; `build:electron` is `tsc -p electron/tsconfig.json`
- Never launch Electron or a browser from automated runs that forbid it; test the decision logic instead

## Tests

Vitest, configured in `vite.config.mts` (do not add a separate `vitest.config.ts`: the `@nx/vite` plugin would take it as the config for the build). Tests: `src/**/*.test.ts` and `electron/**/*.test.ts`.
